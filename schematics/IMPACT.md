| 2026-10-08 | use    | several             | The schematics edit existing TypeScript and JavaScript files (barrels, `@Module` metadata, controllers, `AppModule`, `eslint.config.mjs`) through `@pbuilder/sdk/typescript` instead of string and regex edits, and the `writeBuffer` is gone. Named ops where they fit (`addImport`), `.modify` with `astLibrary` otherwise; no ts-morph dependency. Three engine facts shaped it, each checked with `builder execute`: a second `modify` on a path in one run is `path-collision` even after an awaited read; every read flushes all open handles, so a path cannot be edited again after any read; `.modify` replaces the message of what its callback throws, so `withAst` carries the error out. A run therefore reads first and queues its edits, and `flush` applies each path on one handle. Regenerating the ordering context with the old and the new schematics gives identical files apart from import order in the controller and blank lines between statements. Hand-writing the 26 regexes was the defect class: they broke on formatting, not on content. |
